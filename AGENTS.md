# Fireball Studios static website

This is a standalone Vite8/TypeScript project for static hosting. All deployment files are in `dist/`; Node.js24 is a development/build tool only. There is no backend, API, database, Next.js runtime or server-side email provider.

- `../website-FB` and the original `/Projects` media library are read-only references. Never edit them from this project.
- Use standard UK English. Keep the official brand mark and the established dark studio direction. Do not invent clients, qualifications, results or technical design claims.
- Use `src/data` for shared content and asset mappings, `src/templates` for semantic generated HTML, `src/components` for browser behaviour, and `src/styles/site.css` for the design system.
- Ordinary film playback uses the supplied Vimeo IDs and explicit launch controls. The home story uses local WebP frames3→6→5. Keep sequence4 available; keep spaceship source6 out of the portfolio.
- Gallery originals and their genuine derivatives belong in `public/images/projects`; animation frames belong in `public/frames`. Do not fabricate missing original stills.
- Preserve the configurator's model credits/licences, static CSP, sandbox and checked lifecycle bridge. Load one iframe only after a visitor chooses to launch it.
- Production contact uses the isolated Netlify-hosted capture form embedded on the GitHub website. Keep CAPTCHA, honeypot, shared validation, exact-origin state/height bridge and field retention. Submissions must be stored in the provider dashboard and notifications configured only to info@fireballstudios.co.uk. Do not claim inbox receipt without a real test. Capture source is in capture/ and src/capture/; its separate capture-dist build is never included in the Pages artifact. No private Netlify/email credentials belong in the site. Optional legacy providers remain explicit settings.
- GA4 is optional and requires explicit production enablement plus visitor consent. Keep equal accept/reject controls, footer preferences and the 90-day choice/cookie policy. No Analytics tag, preconnect or measurement request may occur before acceptance; no GA on previews, redirects, 404, viewer or enquiry capture. Keep Enhanced Measurement off, advertising consent denied and form/query data out of approved page/referrer payloads. Google reCAPTCHA is a separate form security service. Use the shared controller, never paste an inline tracking snippet. See `docs/ANALYTICS.md`.
- All page links and assets must work beneath a GitHub Pages repository prefix, without a SPA rewrite. Edit source templates, not generated HTML.
- Default local builds are noindex previews. The owner authorised GitHub publication and replacement at fireballstudios.co.uk on 9 November 2026. The production workflow uses the approved canonical URL and indexing variable. Preserve the old site backup and every original project; do not change DNS, mailbox records or hosting/billing settings without task authorisation. See docs/LIVE_LAUNCH.md.
- Read `docs/PROJECT_GUIDE.md`, `docs/DEPLOYMENT.md` and `docs/ASSET_CREDITS.md`. Respect GitHub Pages' published hosting restrictions; technical compatibility is not a statement of hosting eligibility.
- Run `npm test` and `npm run build` after functional changes. Keep `.archive`, local environment files, dependencies and generated output out of source control.
